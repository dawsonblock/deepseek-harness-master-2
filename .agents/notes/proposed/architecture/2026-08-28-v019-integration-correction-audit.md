# Agent Note: v0.19 integration correction — qualify the resolved composition, not the packages

Status: proposed

English | [中文](2026-08-28-v019-integration-correction-audit.zh.md)

## Problem

An independent source audit of the v0.19 evaluation path found that the effective runtime composition does not match the architecture the evaluation claims to measure. Individual packages contain real security mechanisms — durable routing, canonical accounting, fail-closed subprocess sandboxing, repair decision logic — but the v0.19 evaluator's Cordis composition does not consistently route all model capabilities through them. The result is that current Batch A results cannot support claims about workspace-isolated, unseen-holdout, real-repository, production-RepairRuntime performance.

The central lesson: qualify the resolved execution composition, not the packages. A package-level test can pass while the actual evaluator bypasses the guarantee that package provides.

### Verified findings

Each finding was confirmed against the current source.

**S0-01: fs-local remains mounted in the v0.19 evaluator.** `generateRepoConfig` in `scripts/v019-trajectory-collector.ts` replaces `bash-local` with `sandbox-local` + `sandbox-policy` + `bash-sandbox` but does not replace `fs-local` with `fs-sandbox`. The model-facing file tools (`tool-fs/read`, `tool-fs/write`, `tool-fs/edit`) route through `fs-local`, which documents that `cwd` is a resolution default, not a containment boundary. The mounted `sandbox-policy` does not constrain `fs-local`. The Bash plane is sandboxed; the filesystem-tool plane is not.

**S0-02: fs-sandbox does not fence reads.** `packages/fs/fs-sandbox/src/index.ts` lines 6–8 state: "this package adds only the per-call POLICY fence on the two mutations. Reads pass through untouched: every mode permits reading." Even if the composition swapped `fs-local` for `fs-sandbox`, reads would remain unrestricted. Write fencing alone is insufficient for workspace-isolated evaluation.

**S0-03: V3 holdouts are model-visible.** `scripts/v019-batch-a-repos.sh` creates holdout files under `tests/*.holdout.test.ts` before calling `init_repo`, so they are committed into the base repository presented to the model. The model can read them.

**S0-04: diagnostic discovery includes holdouts.** Every generated repo's Vitest config uses `include: ['tests/**/*.test.ts']`. Holdout files match `tests/**/*.test.ts`. All 15 V3 tasks use `npm test` as the diagnostic command. The diagnostic run executes the holdout, then the harness runs the same holdout again afterward. The V3 designation is invalid: the holdout is not unseen.

**S0-05: Batch A is synthetic, not real-repository.** The corpus header says "25 real-repository benchmark tasks" but every manifest has `source: 'synthetic'` and `REPO_BASE` is `file:///tmp/v019-batch-a-repos`. The repositories are generated by `scripts/v019-batch-a-repos.sh`. Batch A is a synthetic multi-repository coding benchmark, not a historical real-world task program.

**S0-06: Task reproduction can false-pass.** Each synthetic repo contains multiple intentionally broken functions at one shared base commit, and one shared fix commit repairs several or all of them. The qualification gate asks whether `npm test` fails at base and passes at fix, but an unrelated broken function can cause the base failure and an unrelated fix can make it pass. The gate does not prove task-specific reproduction.

**S1-01: v0.19 evaluator uses the v018 script loop, not production RepairRuntime.** `scripts/v019-trajectory-collector.ts` imports `runRepairLoop` from `./v018-repair-loop.ts` and calls it directly. The production `RepairRuntime` package is not mounted in `packages/bundle/base/cordis.patch.yml`. Batch A validates an experimental script loop around `decideRepair()`, not the production durable-execution pipeline.

**S1-02/S1-03: Rollback and provenance are optional.** `RepairRuntime` only runs rollback when `deps.rollbackProvider !== undefined`. The v019 trajectory collector sets `rollbackUsed: false` unconditionally. The experimental repair prompt says "The workspace state from the previous attempt is preserved." Batch A cannot provide evidence for rollback correctness, transactional repair, or rollback economics.

**S1-04: Verification is not workspace-content-bound.** `GoalService.completeVerified()` requires the latest durable event to be `goal/verification` with matching goal revision and verifier registry fingerprint, but the verification receipt contains no workspace content hash. An external filesystem mutation that emits no session event leaves the verification receipt valid.

**S1-05: Durable evidence stores raw verifier output.** Production `RepairRuntime` builds the raw `FailurePackage`, persists `repair/evidence` with raw `failedCriteria`/`failingTests`/`typeErrors`/`buildErrors`, and sanitizes only when generating the next model prompt via `projectFailureForModel()`. The session ledger, checkpoint, and export can retain unsanitized verifier output.

**S1-06: Seatbelt workspace-isolated is not workspace isolation.** `packages/sandbox/sandbox-local/src/profiles.ts` documents that Seatbelt uses `allow-all-reads` plus an explicit protected-path denylist, not an allowlist. `packages/sandbox/sandbox-policy/src/index.ts` defaults `protectedReadPaths: []`. A default macOS workspace-isolated composition can amount to allow-all-host-reads while the system prompt says "The process may read and write only within the session workspace."

**S1-07: releaseToAuto overwrites undecidable authority.** `reconstructSelectionState()` returns `{ undecidable: true }` for a future authority schema. `releaseToAuto()` checks `prior === undefined || (!('undecidable' in prior) && prior.mode === 'auto')`; an undecidable state fails both conditions and falls through to `appendState`, overwriting the unknown state with auto.

**S1-08: Unknown pricing becomes $0.** The turn runner does `pricing === undefined ? 0 : calculateCost(...)`. Unknown model aliases or pricing-registry errors make economic metrics look artificially better.

**S1-09: Metrics do not filter benchmarkEligible.** `computeMetrics()` documents "Only `benchmarkEligible` trajectories contribute" but filters only by `modelCapabilityStatus !== 'NOT_EVALUATED'`. The B0/benchmark separation is operational, not enforced in the metrics function.

**S1-10: replayMismatchRate is hard-coded zero.** `v019-metrics.ts` returns `replayMismatchRate: 0` without deriving it from trajectory evidence. A reported zero does not mean replay was tested.

**S2-01: Per-attempt changedFiles is inaccurate.** The trajectory collector calls `getChangedFiles(workspace)` at mapping time for every attempt, so each attempt receives the final workspace diff rather than its own.

**S2-02: Latency excludes verification.** The turn runner times only `runFixtureTurn`; verification runs separately. `totalLatencyMs` measures model execution, not wall-clock task latency, but the repair budget uses it as elapsed time.

**S2-03: Sandbox qualification skip counted as pass.** The symlink tests in `scripts/verify-sandbox-read-isolation.ts` catch errors and push `{ passed: true }`, counting a skip as a pass and aborting the rest of the suite.

**S2-04: Source manifest is stale.** `FULL_FILE_MANIFEST.sha256` has 2 checksum mismatches and 29 unlisted files relative to the current archive, primarily the v0.19 work.

## Proposal

Pause Batch A. Execute a dedicated integration-correction milestone before spending more provider money or collecting benchmark data. The objective is to make the effective runtime composition match the architecture being claimed and measured.

### Phase 0: Freeze and classify

Record these findings (this note). Reclassify Batch A as `v019-synthetic-multirepo-validation-v1`, not a real-repository benchmark. Invalidate current V3 holdout claims. No controller-policy modifications.

### Phase 1: Filesystem security plane

Replace `fs-local` with `fs-sandbox` in qualified evaluation compositions. Implement read fencing in `fs-sandbox`: `authorizeRead(path, context)` and `authorizeWrite(path, context)` with canonical-path resolution (normalize, resolve, realpath, symlink chain, compare against allowed roots). For `workspace-isolated`: reads allowed within workspace and explicit immutable runtime roots; writes allowed within workspace and private temp; everything else denied. Add adversarial in-process filesystem tests covering workspace reads/writes, parent traversal, absolute outside paths, symlink escapes, and multi-hop symlink chains. Test through `tool-fs/read`, `tool-fs/write`, `tool-fs/edit`, not only low-level helpers.

### Phase 2: Honest subprocess isolation

Split backend guarantees: bwrap (read allowlist, write allowlist, private temp, network deny), Landlock (read allowlist, write allowlist, fix private temp), Seatbelt (protected-read denylist, not workspace-only reads). Seatbelt + workspace-isolated + empty `protectedReadPaths` must be a configuration error. Add private temp directories per execution (`TMPDIR`, `TMP`, `TEMP`). Default network deny for isolated eval workers; the provider API call originates from the harness process, not the untrusted subprocess.

### Phase 3: Transactional repair

Add a `qualified` repair mode that requires `rollbackProvider`, `workspaceProvenanceProvider`, and `holdoutVerifier` (for V3). Startup fails if required dependencies are absent. Wire a harness-owned rollback implementation (git worktree or workspace content snapshot) in evaluation. Persist rollback provenance: `workspaceBeforeHash`, `workspaceAfterHash`, `rollbackTargetHash`, `rollbackResultHash`.

### Phase 4: Workspace-bound verification

Add `workspaceHash` to the verification receipt. Completion requires `currentWorkspaceHash == verification.workspaceHash`. SHA-256 over a deterministic workspace snapshot excluding `.git`, `node_modules`, `dist`, build caches, private temp, and session artifacts.

### Phase 5: Sanitize evidence before persistence

Insert a `DurableEvidenceSanitizer` between raw verifier output and `repair/evidence` persistence. Redact Authorization headers, Bearer tokens, API keys, passwords, DB URLs with credentials, AWS credentials, cookies, JWTs, private-key blocks, and `.env` secret assignments. Use case-insensitive patterns. Raw evidence may exist only in a privileged non-ledger debug facility.

### Phase 6: Fix authority mutation

`releaseToAuto` must refuse undecidable state: `absent → may create Auto; known Auto → idempotent; known Manual → release to Auto; undecidable/future → DENY`. Use compare-and-set (`releaseToAuto(expectedAuthorityVersion)`) to avoid races.

### Phase 7: Evaluation architecture

Stop using `v018-repair-loop.ts` as the benchmark runtime. The evaluation should exercise the production `RepairRuntime` → `RepairController` → durable model authority → routing decision → provider → verifier → rollback/provenance → replay pipeline. Generate an effective runtime manifest at startup by resolving the Cordis composition. Qualification compares claims against this manifest. Invariant: CLAIM = RESOLVED COMPOSITION = EXECUTED PATH.

### Phase 8: Holdout architecture

Remove holdouts from the model workspace. Store them externally under `qualification/holdouts/<task-id>/`, owned by the harness. Run holdouts from a verifier-owned location. Diagnostic commands must not discover holdouts: use `tests/diagnostic/**/*.test.ts` for diagnostic include, not `tests/**/*.test.ts`. Add a preflight check that asserts holdout files are absent from diagnostic discovery.

### Phase 9: Replace Batch A corpus

Rename current Batch A to `v019-synthetic-multirepo-validation-v1`. Preserve it as a systems benchmark. Build a real Batch A from historical open-source tasks with task-specific reproduction gates: the specific task regression fails at base and passes at the reference fix, not merely `npm test` fails.

### Phase 10: Structured diagnostic evidence

Capture failing test names, assertion differences, TypeScript errors, build errors, stack traces, exit codes, and relevant stdout/stderr. Sanitize before persistence. Produce a `FailurePackage` with actual information, not "Verification commands did not pass."

### Phase 11: Accounting corrections

Unpriced usage must fail qualification (`UNPRICED_USAGE` → control-plane failure), not become $0. Separate `modelLatencyMs`, `diagnosticLatencyMs`, `holdoutLatencyMs`, `rollbackLatencyMs`, and `totalWallClockMs`. Repair time budget uses `totalWallClockMs`.

### Phase 12: Metrics corrections

Filter by `benchmarkEligible === true && modelCapabilityStatus !== 'NOT_EVALUATED'`. Replace hard-coded `replayMismatchRate: 0` with `null` / `not-measured` or back it with actual replay records. Capture per-attempt filesystem diffs via before/after snapshots, not final-workspace diff at mapping time.

### Phase 13: Sandbox qualification

Replace skip-as-pass with skip-as-incomplete. Required qualification report: `required=9, executed=9, passed=9, skipped=0, failed=0`. Add the missing in-process file-tool tests. The complete sandbox qualification needs both subprocess and in-process tool planes.

### Phase 14: Security qualification gate

Create `v019-security-qualification-v1` covering filesystem tool plane, subprocess plane, repair transactionality, verification binding, evidence sanitization, authority semantics, accounting, and composition manifest generation. Nothing goes to real Batch A until this is green.

### Phase 15: v0.18 erratum

Do not move the v0.18.0 tag. Publish a qualification clarification: durable routing/accounting/replay, subprocess fail-closed wrapper, repair decision logic, and approval denial remain supported. Complete workspace read isolation, default transactional rollback, required provenance, and integrated RepairRuntime composition were not established by v0.18.0 qualification.

### Phase 16: Post-security smoke and freeze

Run one cheap B0 task to verify effective composition, fs-sandbox, read fence, network deny, private temp, RepairRuntime, rollback, provenance, accounting, and verification hash. Freeze `v019-secure-eval-v1`. Then construct 25 historical real tasks and start the real Batch A.

## Alternatives considered

**Continue Batch A and fix issues later.** The evaluation is already spending provider money on a path with invalid V3 holdouts, no filesystem isolation, and no production RepairRuntime. Data collected now cannot be retroactively made valid. The cost of pausing is lower than the cost of invalid benchmark data.

**Fix only the filesystem plane and continue.** The holdout visibility, broad reproduction gates, and script-loop runtime are independent validity defects. Fixing one does not address the others.

**Archive the v0.18 qualification and start fresh.** The v0.18 mechanisms that are real (routing, accounting, replay, subprocess fail-closed, repair decisions) remain valuable. An erratum clarifying scope is more honest than invalidation and preserves the evidence that was correctly established.

## Acceptance criteria

- `generateRepoConfig` in `scripts/v019-trajectory-collector.ts` mounts `fs-sandbox` instead of `fs-local`, and a composition-level regression test asserts the filesystem provider is `fs-sandbox` for workspace-isolated evaluation.
- `fs-sandbox` implements `authorizeRead` and `authorizeWrite` with canonical-path resolution; adversarial in-process tests through `tool-fs/read`, `tool-fs/write`, `tool-fs/edit` verify zero filesystem escapes including symlink chains.
- Holdout test files are absent from the model workspace and from diagnostic test discovery; a preflight check asserts this.
- Batch A is renamed to `v019-synthetic-multirepo-validation-v1`; the real-repository label is removed.
- Task-specific reproduction gates verify that the specific task regression fails at base and passes at the reference fix, not merely that `npm test` fails.
- The v019 evaluator uses production `RepairRuntime`, not `v018-repair-loop.ts`; `rollbackUsed` reflects actual rollback events.
- `releaseToAuto` refuses undecidable authority state; a test verifies that a future-schema event followed by Auto produces zero new authority events.
- `computeMetrics` filters by `benchmarkEligible === true && modelCapabilityStatus !== 'NOT_EVALUATED'`.
- `replayMismatchRate` is `null` or backed by actual replay records, never hard-coded zero.
- Unknown pricing produces `UNPRICED_USAGE` control-plane failure, not $0 cost.
- Sandbox qualification reports `skipped` separately from `passed`; a required skip means `INCOMPLETE`.
- `v019-security-qualification-v1` passes across filesystem, subprocess, repair, verification, evidence, authority, and accounting planes.
- A v0.18.0 qualification erratum is published clarifying what was and was not established.
- One post-security B0 smoke task verifies the effective composition before any real Batch A task runs.

## Risks

The correction phase delays the 75-task benchmark program. The delay is justified: benchmark data from an invalid composition is worse than no data. The largest implementation risk is the fs-sandbox read-fencing work, which requires canonical-path resolution robust against symlink chains and TOCTOU races. The Seatbelt honesty correction may require renaming a security tier that downstream configuration references. The RepairRuntime mounting requires understanding the production composition path that the v018 script loop bypassed.
