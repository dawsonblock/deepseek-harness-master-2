# Agent Note: v0.17.1 影子模式基础设施 — 更丰富特征和多目标模型

Status: implemented

[English](2026-08-25-v0171-shadow-mode-infrastructure.md) | 中文

## 问题

v0.17.0 离线评估证明了学习循环端到端工作，但发现 7 个复杂度评分器特征不足以预测 Pro 必要性。3 个 pro-necessary 案例复杂度信号为零。在现有特征空间上调整阈值无法将它们与 25 个 Pro 不必要的案例分离。数据集（30 配对）也太小，无法训练有意义的路由器。

## 决策

发布 v0.17.1 影子模式基础设施：更丰富的路由前特征、确定性任务类型分类器、多目标模型和影子评估框架。启发式路由器保留控制；学习型路由器并行运行，记录预测用于离线评估。不实时部署学习型路由器。

### 影子模式架构

```
                    LIVE TASK
                       |
                       v
              Pre-routing features
                 /     |      \
                /      |       \
        structural   semantic   history
                \      |       /
                 \     |      /
                       v
               Learned predictor
                       |
              +--------+--------+
              v                 v
        shadow choice      heuristic choice
                               |
                               v
                         ACTUAL EXECUTION
                               |
                               v
                         RoutingOutcome
                               |
                               v
                   shadow-policy evaluator
```

学习型路由器预测；启发式路由器控制。离线报告记录每个影子选择、概率、特征向量、模型版本和配对结果。在运行时发出方拥有事件之前，不声明会话日志事件。

### 更丰富的路由前特征（25 个特征，4 个族）

1. **复杂度**（7）：现有启发式评分器信号
2. **结构**（11）：输入 token、消息数、工具模式数、文件数、代码块、结构化数据大小、输出格式、JSON 指示器、多文件指示器、工具需求、验证标准数
3. **类别**（1）：来自确定性分类器的 `taskType`，带 `expectsProAdvantage` 标志
4. **历史**（6）：按任务类型的 Flash/Pro 成功率、救援率、近期失败率、成本差异、样本数

历史特征在冻结数据集上零初始化。一旦影子模式跨会话积累配对结果，它们变得有信息性。

### 确定性任务类型分类器

关键词和结构分类器将轮次文本映射到 9 种任务类型之一：`factual-explain`、`structured-transform`、`reasoning-proof`、`code-edit`、`debugging`、`planning`、`tool-heavy`、`long-context`、`simple-factual`。无嵌入模型——分类器廉价、确定性，测试类别特征在添加语义特征前提供多少价值。

分类器正确识别 `structured-transform` 为期望 Pro 优势——v0.16.0 基准显示的 Pro 必要任务类型。这是对 v0.17.0 的真正改进，后者对这些任务零信号。

### 多目标模型

两个逻辑回归和一个线性回归在相同特征上训练：

- P(Flash 通过)：预测 Flash 验证成功
- P(Pro 通过)：预测 Pro 验证成功
- 预期成本差异：线性回归预测 Pro - Flash 成本差异

路由决策是效用差异上的阈值：当 `P(Pro 通过) - P(Flash 通过) >= 阈值` 时选择 Pro。

### 影子评估框架

指标层次（按优先级）：

1. 验证成功率——主约束
2. 每已验证任务成本——主优化目标
3. ProNecessity 召回——不遗漏真正需要 Pro 的任务
4. ProWaste 率——最小化不必要的 Pro
5. 修复率
6. 中位/p90 延迟
7. Pro 利用率

### 推广学习型路由器的发布门控

| 标准 | 目标 |
|---|---|
| 验证成功 | 无实质性下降 |
| 每已验证任务成本 | >=15-20% 改善 |
| ProNecessity 召回 | >=90% |
| ProWaste 率 | 实质性降低 |
| 影子样本量 | 足够大的置信区间 |

所有标准在 30 配对时为"数据不足"。v0.17.1 目标：100-200 标注任务。v0.17.2 目标：500+ 任务。

## 测量结果

### 测试分区（3 个任务类，6 个示例）

| 策略 | 验证 | 成本/已验证 | ProNecessity 召回 | ProWaste 率 | Pro 利用率 |
|---|---:|---:|---:|---:|---:|
| Flash-only | 50.0% | $0.001054 | 0% | 0% | 0% |
| Pro-only | 66.7% | $0.002248 | 100% | 33% | 100% |
| 启发式路由器 | 50.0% | $0.001054 | 0% | 0% | 0% |
| 学习型路由器 | 50.0% | $0.001054 | 0% | 0% | 0% |

30 配对评估对所有测试任务赋予 P(Flash) == P(Pro)。18 个训练示例下，两个概率回归收敛到相似权重——模型无法区分 Flash 和 Pro 通过概率。任务类型分类器正确识别 `structured-transform` 为期望 Pro 优势，但模型无法使用此信号，因为两个目标相同。

### 任务类型分类

确定性分类器正确识别：

- `structured-transform` 为 `structured-transform`（期望 Pro：是）
- `reasoning-proof` 为 `reasoning-proof`（期望 Pro：是）
- `factual-explain` 为 `factual-explain`（期望 Pro：是）
- `code-edit` 为 `code-edit`（期望 Pro：否）
- `arithmetic` 为 `simple-factual`（期望 Pro：否）

部分误分类：`debug-off-by-one` 分类为 `unknown`，`verify-algorithm` 分类为 `factual-explain`，`long-context-summary` 分类为 `planning`。语义嵌入会修复这些边缘情况。

## 考虑的替代方案

### 为什么不立即部署学习型路由器？

30 个示例且所有测试任务 P(Flash) == P(Pro)，学习型路由器相比 Flash-only 无改善。部署噪声。发布门控要求 >=15-20% CPT 改善和 >=90% ProNecessity 召回——此样本量下均不可达。

### 为什么不现在添加语义嵌入？

优先顺序正确：结构特征优先，类别特征其次，历史特征第三，语义嵌入仅在更简单特征留下大量未解释 Pro 必要性时。确定性任务类型分类器已识别 Pro 必要任务类型。在穷尽更简单特征前添加嵌入会增加复杂性而无证明价值。

### 为什么不使用联合模型？

捕获 Flash 和 Pro 通过概率相关性的联合模型比两个独立逻辑回归更丰富。但 18 个训练示例下联合模型会过拟合。独立模型是此样本量下适当的复杂度。联合模型是数据集扩展后的 v0.18+ 关注点。

### 为什么不交叉验证？

15 个任务类上的留一任务交叉验证产生 15 折，但每折在 14 个任务上训练、1 个任务上测试——每任务 2 个示例的高方差。单一 60/20/20 分割更可解释。数据集扩展到 100+ 任务后应添加交叉验证。

## 后果

离线影子基础设施包含更丰富特征（25 vs 7）、多目标模型、确定性任务类型分类器、预测记录类型和带指标层次的评估框架。任务类型分类器正确识别 Pro 必要任务类型——v0.17.0 中完全缺失的信号。

数据集仍是瓶颈。30 配对下，多目标模型收敛到 P(Flash) == P(Pro)，因为无法从 18 个训练示例中学到差异。基础设施已为 100-200 任务准备；数据集未准备。

路由器插件没有影子预测发出方或序列化模型加载器。添加持久影子事件要求在同一变更中提供运行时生产者、可忽略追加语义、生成的持久化词汇和 SDK 投影。

### 资格评估限制

1. **样本量**：[扩展资格评估](2026-08-25-v0172-expanded-shadow-qualification.zh.md)包含 100 个配对和六个 Pro 必要示例，低于推广规模。

2. **运行时影子收集**：预测仍是离线报告记录，而不是会话事件。

3. **历史特征**：评估器在基准内部计算仅使用过去信息的历史；生产会话尚未积累相同统计。

4. **交叉验证**：50 任务语料使用一个任务隔离的训练/验证/测试分割。

5. **联合模型**：Flash 和 Pro 通过概率仍是独立逻辑目标。
