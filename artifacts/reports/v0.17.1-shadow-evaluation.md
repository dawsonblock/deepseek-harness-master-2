## Features (25 pre-routing, featureVersion=1)

Three feature families:

1. **Complexity** (7): existing heuristic scorer signals
2. **Structural** (11): input tokens, message count, tool schemas, files, code blocks, structured-data size, output format, JSON indicator, multi-file indicator, tool requirement, verification criteria
3. **Categorical** (1): task type from deterministic classifier
4. **Historical** (6): Flash/Pro success rates, rescue rate, recent failure rate, cost difference, sample count

Historical features are zero-initialized for the frozen dataset (no prior history).
They become informative once shadow mode accumulates paired outcomes across sessions.

## Model: Multi-Target Logistic Regression

Model version: 1
Training size: 18
Optimal proCostThreshold (from validation): 0.1

Three separate logistic regression models:
- P(Flash passes): predicts Flash verified success
- P(Pro passes): predicts Pro verified success
- Expected cost delta: predicts Pro - Flash cost difference

Routing decision: choose Pro when P(Pro passes) - P(Flash passes) >= threshold.

## Release gate for promoting learned router

The learned router should only replace the heuristic router when:

| Criterion | Target | Current |
|---|---|---|
| Verified success | no material degradation | insufficient data |
| Cost per verified task | >=15-20% improvement | insufficient data |
| ProNecessity recall | >=90% | insufficient data |
| ProWasteRate | materially lower | insufficient data |
| Shadow sample size | large enough for confidence intervals | 30 (too small) |

All criteria are "insufficient data" because the dataset has only 30 pairs.
v0.17.1 target: 100-200 labeled tasks. v0.17.2 target: 500+ tasks.

## Limitations

- 30 examples is too small to train a meaningful router. The infrastructure is correct; the dataset is the bottleneck.
- Historical features are zero-initialized (no prior history). They become informative once shadow mode accumulates data.
- The task-type classifier is deterministic and may misclassify edge cases. Embeddings should be added if categorical features leave substantial unexplained Pro-necessity.
- No cross-validation; single 60/20/20 split has high variance with 30 examples.
- The multi-target model trains three independent logistic regressions. A joint model capturing P(Flash) and P(Pro) correlations would be richer.
- Dataset expansion to 100-200 tasks requires live API calls (credential rotation needed).
- Shadow mode live deployment requires the `model/shadow-routing-prediction` event to be wired into the router plugin.
