# v0.15.5-rc.1 Baseline Failure Report

## Method

The repository has a single commit (`fb7e7e8`) that already includes the v0.15.5 P0 changes, so there is no pre-v0.15.5 git baseline to check out. This report is a change-surface attribution analysis, not historical proof that these failures predate v0.15.5. Each failure is classified by cross-referencing its owning test file and source path against the v0.15.5 changed-files list. A failure is attributed as "outside the v0.15.5 change surface" when:

1. Its owning source/test file is not in the v0.15.5 changed-files list, OR
2. Its owning file is changed but the diff hunk is in a different code section than the failing assertion, OR
3. Its root cause is environmental nondeterminism (timing, event ordering) independent of model-selection logic.

This establishes a defensible attribution but does not prove the failures historically predate the release. A pre-v0.15.5 git baseline would be required for that stronger claim.

## Snapshot replay failures (4/128)

All four are nondeterministic output in ignorable events, not model-selection logic.

### 1. parallel-tool-calls

- **Root cause:** parallel `tool/settled` events for concurrent tool calls appear in nondeterministic order in the session log.
- **v0.15.5 relation:** none. The `tool/settled` event ordering is determined by the tool executor's concurrent dispatch resolution, which v0.15.5 does not touch.
- **Fix recommendation:** sort `tool/settled` events by `callId` or `dispatchSeq` in the snapshot normalizer, or exclude their ordering from canonical comparison.

### 2. persistent-pwsh-tool-turn

- **Root cause:** `terminal/settlement` event carries `durationMs` with millisecond timing variance (26938 vs 26940).
- **v0.15.5 relation:** none. Terminal settlement timing is owned by the pwsh executor, not model selection.
- **Fix recommendation:** tokenize or normalize `durationMs` in the snapshot scrubber.

### 3. subagent-parallel

- **Root cause:** same as parallel-tool-calls — parallel `tool/settled` ordering for concurrent subagent calls.
- **v0.15.5 relation:** none.
- **Fix recommendation:** same as parallel-tool-calls.

### 4. sdk.snapshot.ts > persistent-tools

- **Root cause:** same nondeterministic `tool/settled` or timing variance propagated through the SDK replay.
- **v0.15.5 relation:** none.
- **Fix recommendation:** same as above.
